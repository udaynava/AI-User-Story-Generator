AI User Story Generator – Team Introduction Brief
Welcome
Welcome to the AI User Story Generator experiment. This brief provides everything you need to get started on this focused development spike.
We aim to explore how AI-assisted tooling can help product and delivery teams efficiently transform unstructured business requirements into high-quality, structured Jira-ready user stories, while maintaining consistency, traceability, and control.
Project Overview
Background
In modern software delivery environments, product managers and business analysts frequently work with unstructured inputs such as emails, meeting notes, or business requirement documents. Translating these into well-formed Jira user stories is:
● Time-consuming
● Inconsistent across teams
● Dependent on individual experience
This results in variability in story quality, unclear acceptance criteria, and inefficiencies during sprint planning and execution.
The Opportunity
This experiment explores whether an internal AI-assisted tool can:
● Convert unstructured requirements into standardized user stories
● Improve consistency in story format and quality 
● Accelerate backlog creation
● Maintain traceability between source input and generated stories
What We’re Building
An internal AI User Story Generator that can:
● Ingest unstructured requirement inputs (text, documents)
● Generate structured Jira-ready user stories
● Produce acceptance criteria using standard formats (e.g., Given/When/Then)
● Suggest metadata such as priority, labels, and story points
● Maintain traceability between input and generated output
● Integrate with Jira to create tickets directly
● Support a lightweight review and approval workflow
Technical Context
Proposed Technology Stack
● Frontend: React and/or Next.js
● Backend / Data: Supabase (Postgres, Auth, Storage)
● Workflow Orchestration: n8n
● LLM Access: Approved tooling (e.g., Requesty)
● Integration: Jira REST API
● UI Components: shadcn/ui
Sample Use Cases
The tool will support common delivery workflows, including:
1. Converting business requirements into Jira user stories
2. Generating acceptance criteria for incomplete stories
3. Standardizing backlog creation across teams
4. Preparing draft stories for sprint planning
5. Accelerating documentation of features from meeting notes
Experiment Scope & Timeline
Duration
This experiment is designed as a short, focused development spike and can be completed incrementally over several weeks.
What This Is
● A proof of concept for AI-assisted backlog generation
● A learning exercise to test structured content generation workflows
● An exploration of guardrails, traceability, and usability
What This Is Not
● A production-ready Jira replacement
● A fully automated backlog management system
● A substitute for product owner decision-making
Success Criteria
At the conclusion of the experiment, we aim to understand:
1. Technical Feasibility
Can React, Supabase, n8n, Jira APIs, and LLM tooling be effectively integrated?
2. Quality of Output
Are generated user stories:
● Clear and actionable?

3. Usability
Does the tool feel like a practical assistant for product teams?
4. Safety and Guardrails
Does the system avoid:
● Hallucinated requirements
● Unsupported assumptions
● Inconsistent or vague acceptance criteria

Core Functional Design
Input Layer
● Free text input
● Document upload (optional)
● Structured form (optional fields)
Processing Layer (n8n + LLM) Steps:
1. Pre-process input 2. Extract key entities (actor, goal, value) 3. Generate: ○ User story ○ Acceptance criteria 4. Add metadata suggestions 5. Validate output against guardrails
Output Layer
● Editable user story view
● Side-by-side comparison (input vs output)
● Export options:
○ Jira ticket creation
○ JSON / CSV
Guardrails & Safety Design
● Only use information explicitly present in input
● Flag missing information instead of guessing
● Enforce structured templates:
○ “As a… I want… So that…”
● Acceptance criteria must be:
○ Testable
○ Specific
● Provide confidence indicators for generated content
Jira Integration Design
● Use Jira REST API to:
○ Create issues
○ Assign issue types (Story, Task)
○ Add labels and metadata
● Map generated fields to Jira schema:
○ Summary → Story title
○ Description → Full story + criteria
● Support dry-run mode before ticket creation

Developer Guidance (IMPORTANT)
When using AI-assisted coding tools (e.g., Copilot, Claude, GPT):
● Validate all generated code before use
● Ensure code is:
○ Correct
○ Secure
○ Maintainable
● Avoid overly verbose or unnecessarily complex implementations
● Prefer simple, modular, and readable code
● Review all API integrations carefully (especially Jira and Supabase)
AI-generated code should be treated as a starting point, not a final solution.
Closing Thoughts
This is an experiment focused on learning and validation. The goal is not perfection, but insight into how AI can responsibly support project delivery workflows.
Whether the outcome confirms feasibility or reveals limitations, both are valuable in guiding future development.
